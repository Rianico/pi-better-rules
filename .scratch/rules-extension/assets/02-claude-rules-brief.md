# Research: Claude Code rules semantics (`.claude/rules`) → Pi mapping

## Summary

Claude Code discovers `*.md` under `.claude/rules/` **recursively**; files **without** `paths:` frontmatter load at launch at **same priority as `CLAUDE.md`**; files **with** `paths:` load **on-demand when Claude reads a matching file**, not at launch. User rules `~/.claude/rules/` load **before** project rules, so **project wins on conflict**; all layers **concatenate, not override**. Path-scoped rules and nested `CLAUDE.md` **do not survive compaction verbatim** — they are summarized away and only reloaded if one of ≤5 re-read files matches again; root `CLAUDE.md`/unscoped rules/auto-memory are **re-injected from disk**.

## Findings

1. **Discovery is recursive, `.md` only, no config** — `All .md files are discovered recursively, so you can organize rules into subdirectories like frontend/ or backend/`. [Memory](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) ; third-party confirms `Every .md file in the tree gets picked up`. [Rules Directory](https://www.buildthisnow.com/blog/guide/mechanics/rules-directory)
2. **Unscoped rules = launch-time, same priority as `CLAUDE.md`** — `Rules without paths frontmatter are loaded at launch with the same priority as .claude/CLAUDE.md`. [Memory](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) ; hierarchy table lists `CLAUDE.md: High` and `Rules Directory: High / Same weight as CLAUDE.md`. [Rules Directory](https://www.buildthisnow.com/blog/guide/mechanics/rules-directory)
3. **`paths:` frontmatter = on-demand, Read-triggered scoping** — `Path-scoped rules trigger when Claude reads files matching the pattern, not on every tool use`. [Memory](https://code.claude.com/docs/en/memory#path-specific-rules) ; example `--- paths: src/api/**/*.ts ---`. [Rules Directory](https://www.buildthisnow.com/blog/guide/mechanics/rules-directory) ; `paths: ["**/*.test.tsx"]` pattern for scattered file types. [Cert Guide 3.3](https://claudecertificationguide.com/learn/3-claude-code-config/3-3-path-specific-rules) ; **Caveat:** community reports path rules fire on `Read` but **not on `Write` alone** — [Issue #23478](https://github.com/anthropics/claude-code/issues/23478) — do not assume Write-trigger without verification.
4. **Glob semantics + budgets** — `**/*.ts` all TS any dir; `src/**/*` under src; `*.md` project-root only; `src/components/*.tsx` direct children only. [Memory](https://code.claude.com/docs/en/memory#path-specific-rules) ; brace expansion e.g. `src/*.{ts,tsx}`; **whole `paths` list shares one budget of 1,000 expanded patterns and 4 MiB**; over-budget patterns used unexpanded (literal braces match nothing); `[` starts bracket expr, escape literal as `\[`; invalid pattern matches nothing, other patterns keep working (pre-v2.1.207 it broke Read; pre-v2.1.217 many braces crashed startup). [Memory](https://code.claude.com/docs/en/memory#path-specific-rules)
5. **User vs project load order / precedence** — `User-level rules are loaded before project rules, giving project rules higher priority`. [Memory](https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/) ; full tier: **Managed policy → User `~/.claude/CLAUDE.md` → Project `./CLAUDE.md` or `./.claude/CLAUDE.md` → Local `./CLAUDE.local.md`**, `ordered from filesystem root down to working directory`, `concatenated into context rather than overriding`. [Memory](https://code.claude.com/docs/en/memory#how-claude-md-files-load) ; `~/.claude` global vs `.claude/` project scope table. [Claude Directory](https://code.claude.com/docs/en/claude-directory)
6. **Symlinks supported + cycle-safe** — `The .claude/rules/ directory supports symlinks... Symlinks are resolved and loaded normally, and circular symlinks are detected and handled gracefully`. [Memory](https://code.claude.com/docs/en/memory#path-specific-rules) ; `ln -s ~/shared-claude-rules .claude/rules/shared`. [Rules Directory](https://www.buildthisnow.com/blog/guide/mechanics/rules-directory) ; for `claudeMdExcludes`, `write the pattern against either path: the file's path under .claude/rules/ or its link target` (pre-v2.1.239 only target matched). [Memory](https://code.claude.com/docs/en/memory#exclude-specific-claude-md-files)
7. **Size / budget guidance** — `target under 200 lines per CLAUDE.md file`; `Claude Code loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file`; auto-memory `first 200 lines or 25KB`; skills `capped at 5,000 tokens per skill and 25,000 total; oldest dropped first`; keep important instructions `near the top of SKILL.md`. [Memory](https://code.claude.com/docs/en/memory) + [Context Window](https://code.claude.com/docs/en/context-window#what-survives-compaction) ; `/doctor` trim check (v2.1.206+), `/context` to verify loaded files. [Memory](https://code.claude.com/docs/en/memory#troubleshoot-memory-issues)
8. **What survives compaction** — `Project-root CLAUDE.md and unscoped rules: Re-injected from disk`; `Auto memory: Re-injected`; `System prompt and output style: Unchanged`; `Rules with paths: frontmatter: reloads as Claude reads files they match`; `Nested CLAUDE.md: reloads as Claude reads files in that subdirectory`; `Files read/edited: re-reads up to five, most recently modified first` (over 5k tokens → path ref only, rules still reload); `Invoked skill bodies: re-injected capped`; `Context hooks added: Summarized`; `SessionStart hooks matching compact source: run and added`. [Context Window](https://code.claude.com/docs/en/context-window#what-survives-compaction) ; `If a rule must persist across compaction, drop the paths: frontmatter or move it to project-root CLAUDE.md`. Same source.
9. **Not enforcement + import/comments mechanics** — `CLAUDE.md ... loaded as user message after system prompt, not as system prompt`; for must-enforce use `PreToolUse hook` or `--append-system-prompt`. [Memory](https://code.claude.com/docs/en/memory#troubleshoot-memory-issues) ; `Block-level HTML comments stripped before injection`; `@path/to/import` expands at launch, relative to importing file, max 4 hops, skips code spans/fences, backtick to escape. [Memory](https://code.claude.com/docs/en/memory#how-claude-md-files-load) ; `--setting-sources` can exclude `project`; `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` opts `--add-dir` memory in. Same page.
10. **Exclusions** — `claudeMdExcludes` glob vs absolute paths, merges across user/project/local/managed, `Managed policy CLAUDE.md cannot be excluded`. [Memory](https://code.claude.com/docs/en/memory#exclude-specific-claude-md-files)

## Gaps

- No official spec for `Write`-trigger; only `Read`-trigger documented + open bug. Next: probe Pi tool layer to decide Read+Write vs Read-only matching.
- Version-gated behaviors (v2.0.64, v2.1.198/207/211/217/239) — need to pin which Pi adopts; no single changelog page fetched.
- No official per-rule file MiB cap (only CLAUDE.md 4 MiB + paths-list 4 MiB/1000 patterns). Next: set Pi budgets explicitly rather than inheriting.

## Conflicts to flag

1. **System/general two-tier injection vs Claude's single high-priority + on-demand split** — Claude has effectively two weights: **always-on high (root CLAUDE.md + unscoped rules)** vs **conditional high (paths-scoped, only while matching files are active)** vs **medium on-demand (skills)**. If Pi injects both `system` and `general` tiers always, everything becomes high-priority-everywhere = `priority nowhere` trap (cf. `development-patterns.md` + `git-convention.md` + `mental-model.md` all always-on). **Fix:** keep always-on tier minimal (invariants only); move domain rules (e.g. git/worktree, runtime-specific) to `paths:`-scoped or skill tier. Severity: medium. Files: `~/.pi/agent/rules/common/*.md`.
2. **Compaction-reload expectation** — Claude re-injects always-on from disk but **summarizes scoped rules away** until re-triggered. If Pi assumes all `.pi/rules` persist across compaction, scoped security/test/migration rules will silently vanish mid-session. **Fix:** document evictable vs persistent; add `SessionStart compact`-equivalent re-injection hook or require re-Read of ≤5 anchor files. Severity: high. Files: `.pi/rules/**/*.md` with `paths:`.
3. **No-reload-on-`/reload` requirement** — Directly conflicts with Claude's **re-read-from-disk after compaction** behavior. No-reload preserves stale edited rules (good for reproducibility, bad for freshness); Claude chose freshness. **Fix:** pick one: (a) snapshot-at-launch + explicit `/reload` to refresh, or (b) Claude-style live re-read; do not mix silently. If (a), `/context` must show snapshot revision. Severity: medium. Files: Pi session bootstrap + `/reload` handler.
